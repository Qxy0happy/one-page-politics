# 真机交付与 TTS 可用性

Status: resolved
Type: spec
交付：`device-tts-release` 分支（jj bookmark，截至 2026-11-20）；工单 01–05 已关闭，release APK 与验收证据见 `app/docs/device-acceptance.md`。
上位文档：`brief.md`（产品语义）、`spec.md`（2026-11-20 冻结实施基线）、`GLOSSARY.md`（术语）。

## Problem Statement

应用已经在模拟器上完成，但我还没有在手机上真正使用过。现在手上只有约 200 MB 的 debug APK，通常需要借助电脑或文件传输安装；手机的中文语音是否可用、声音是否正常，都还没有验证。更麻烦的是，如果语音引擎报错或迟迟不回调，播控条可能停在“播放中”却没有声音，也不会进入下一条——这会让“磨耳朵”完全不可用，并让我怀疑其他功能是否可靠。

我需要一个能直接装进手机、离线可用、语音失败时能明确说明原因并继续工作的版本，以及一套可以在每次重新构建后重复执行的验收步骤。

## Solution

交付一个用于个人侧载的 release APK，并在真机上完成一次可重复的验收：安装、离线冷启动、TTS 试听与整队朗读、暂停/继续/上一条/下一条/语速/循环、无中文语音时的降级、强制停止后的进度保留、导入/导出，以及四个 Tab 的关键流程。

TTS 侧增加中文语音选择、引擎与语音诊断、试听、错误回调与超时看门狗，保证引擎异常时不会卡死；release 合并清单不声明 `INTERNET` 权限；APK、校验和与验收证据一并记录。学习算法、内容与四 Tab 的视觉结构保持不变。

## User Stories

1. 作为备考学生，我希望得到一个可以直接安装到手机的 release APK，以便不依赖电脑和 `adb` 使用应用。
2. 作为备考学生，我希望 APK 体积明显小于当前约 200 MB 的 debug 包，以便快速传输和安装。
3. 作为备考学生，我希望 release APK 不声明 `INTERNET` 权限，以便确认应用完全离线。
4. 作为备考学生，我希望安装后首次启动直接得到内置的一页纸，以便不配置任何文件就开始复习。
5. 作为备考学生，我希望在飞行模式下冷启动应用，以便在教室、地铁等无网络环境使用。
6. 作为备考学生，我希望应用在强制停止后重新打开仍保留三态、标星、备注与真题记录，以便学习进度不丢失。
7. 作为备考学生，我希望 release 构建沿用当前应用 ID 与签名，以便覆盖安装更新时不清除数据。
8. 作为备考学生，我希望知道 APK 的 SHA-256 与构建版本，以便确认安装的是正确文件。
9. 作为备考学生，我希望手机的中文语音只支持 `zh-TW` 或 `zh-HK` 时仍能朗读，以便不被 `zh-CN` 的硬编码挡住。
10. 作为备考学生，我希望应用自动选择手机上最合适的中文语音，以便获得可理解的朗读。
11. 作为备考学生，我希望在播控条看到当前引擎与语音区域，以便在无声时判断问题所在。
12. 作为备考学生，我希望有一个“试听”按钮，以便在开始整队朗读前先确认扬声器与语音正常。
13. 作为备考学生，我希望语音引擎报错或长时间无响应时自动跳过当前条目并继续，以便队列不会永久卡住。
14. 作为备考学生，我希望跳过若干条后看到明确的失败提示，以便知道需要检查系统文字转语音设置。
15. 作为备考学生，我希望系统没有中文语音时看到安装路径与“重试”，以便安装语音数据后无需清除应用数据即可恢复。
16. 作为备考学生，我希望快速点击播放、暂停、上一条、下一条时不会出现两路声音重叠，以便播控行为可预测。
17. 作为备考学生，我希望暂停后继续从当前条目开始，而不是从头开始，以便跟上进度。
18. 作为备考学生，我希望上一条/下一条只移动一条，并且播放态下立即切换，以便定位到想听的条目。
19. 作为备考学生，我希望语速切换在真机引擎上生效，以便按自己的听力习惯调整。
20. 作为备考学生，我希望单列表循环在真机上可用，以便反复磨同一组条目。
21. 作为备考学生，我希望是非条目朗读“正确/错误 + 解析”，以便听到判断依据而不只是结论。
22. 作为备考学生，我希望播控条使用打开时的筛选快照，以便朗读内容与我看到的列表一致。
23. 作为备考学生，我希望关闭播控条立即停止朗读，以便随时中断。
24. 作为备考学生，我希望 TTS 诊断不依赖网络，以便完全离线使用。
25. 作为备考学生，我希望语音引擎缺失或崩溃时其他 Tab 仍可用，以便不影响刷眼与做题。
26. 作为备考学生，我希望在手机上完成一次导入、导出与恢复内置一页纸，以便内容维护流程在真机可用。
27. 作为备考学生，我希望四个 Tab 的关键流程在真机上走通，以便确认模拟器通过不等于手机可用。
28. 作为备考学生，我希望有一份可重复的验收清单与证据记录，以便每次重新构建后按同样步骤检查。
29. 作为备考学生，我希望安装与验收过程不安装新的工具链组件，以便遵守本机的工具链约束。
30. 作为备考学生，我希望应用保持现有的视觉与学习算法，以便这次交付只解决可用性，不引入回归。
31. 作为备考学生，我希望 TTS 失败时不影响已保存的学习状态，以便试听和朗读没有副作用。
32. 作为应用维护者，我希望 release 构建的权限、签名与版本号可以被命令验证，以便交付物可核对。
33. 作为应用维护者，我希望真机验收结果记录设备型号、Android 版本、语音引擎与所选语言，以便后续比较。
34. 作为应用维护者，我希望 TTS 的平台异常可以通过日志定位，以便在真机上复现后快速修复。

## Implementation Decisions

### 1. 交付形态与签名

- 交付 universal release APK，用于个人侧载；不生成 AAB，不进入应用商店，不做自动更新。
- release 继续使用当前构建配置中的本机 debug 签名，不新建密钥库。理由：这是服务至 2026-12-19 的短期个人工具，新建密钥库会引入密码与备份负担，而 debug 签名在本机稳定可用。
- 明确记录该取舍：APK 只用于个人手机，不可用于商店分发；换机器重建时需要保留同一 debug keystore，否则无法覆盖安装，只能卸载后重装并丢失本机进度。
- 保持 `applicationId` 不变；首个手机安装使用当前版本号。后续更新递增构建号，版本号策略不在本规格内展开。
- 构建完成后记录 APK 路径、文件大小、SHA-256、版本号与签名证书摘要。

### 2. release 权限与离线约束

- release 合并清单必须不含 `android.permission.INTERNET`；debug/profile 可以保留 Flutter 调试所需权限。
- 保留 `android.intent.action.TTS_SERVICE` 查询，供 `flutter_tts` 发现系统语音引擎。
- 不新增存储权限；导入/导出继续使用系统文件选择器。
- 构建后用 `aapt2 dump permissions` 检查合并清单。如果某个插件把 `INTERNET` 合并进来，在主清单中加入 manifest merger 的移除规则，再重新构建并复查。
- 用 `apksigner verify --print-certs` 确认 APK 已签名；用 `aapt2 dump badging` 核对包名、版本号与 SDK 范围。

### 3. TTS 中文语音选择

- 初始化时同时读取引擎列表、默认引擎与语言列表；任何一项失败都不阻止其他项继续探测。
- 语言标签按 BCP-47 处理，大小写不敏感，`_` 归一化为 `-`。
- 选择顺序：
  1. 精确 `zh-CN`；
  2. 任意 `zh-Hans*`；
  3. 语言列表中的第一个 `zh-*`；
  4. 依次探测 `zh-CN`、`zh-TW`、`zh-HK`、`zh` 的可用性；
  5. 无可用中文时判定为不可用。
- 对每个候选调用 `setLanguage` 并检查返回值；返回失败时继续尝试下一个候选，不得直接假定 `zh-CN` 成功。
- 暴露只读诊断状态：是否可用、所选语言、引擎名称、语言数量、最近一次错误。引擎名称取不到时显示“系统默认”。
- 不下载、不捆绑语音数据；语音数据由系统文字转语音设置提供。

### 4. TTS 播放状态机

- 同一时刻只允许一个播放循环。播放、暂停、继续、上一条、下一条、关闭面板都递增一个会话代次；旧循环在每次 `await` 之后检查代次，不匹配即退出。
- 暂停、上一条、下一条与关闭必须显式结束当前 utterance 的等待，不得留下悬挂的 Future；停止后旧循环不得再推进索引或写入状态。
- 每条 utterance 都有超时看门狗，默认 60 秒；测试通过构造参数注入更短的超时。超时后调用停止、记录失败、跳过当前条目并继续下一条。
- 同时订阅平台错误回调。错误回调到达时立即结束当前 utterance 的等待，不等待看门狗到期。
- `speak` 返回 0 视为本次未开始，按失败处理。
- 连续 3 条失败后停止整队，进入降级态并显示“语音引擎无响应”；用户可重试。单条失败只跳过，不停止整队。
- 暂停后继续从当前索引开始；上一条/下一条在播放态下立即切换，在暂停态下只移动索引。
- 循环模式在一轮结束后回到索引 0，仍受代次与降级态约束。
- 关闭播控条调用停止并释放引擎；释放后不得再触发 UI 通知。
- 朗读文本格式化（题干、结论、是非判断与解析）提取为纯函数，由单元测试覆盖；播控条不重复拼接文本。
- TTS 的任何失败都不得写入条目的三态、标星、复习次数或真题记录。

### 5. TTS 播控条

- 在现有播控条上增加一行诊断信息：引擎名称与所选语言；文字超长时省略，不换行挤压控件。
- 增加“试听”按钮，朗读一句固定中文短句；试听不改变队列索引，不写入学习状态。试听失败时用 SnackBar 显示原因，按钮恢复可用。
- 增加失败提示区：显示已跳过条数与最近错误，并提供“重试”。重试从当前索引继续；若引擎已判定不可用，则重新执行初始化。
- 保留现有播放/暂停、上一条/下一条、1.0x/1.25x/1.5x、单列表循环与进度显示。
- 无中文语音时保留现有说明与“重试”，并补充系统设置路径的文字说明；不新增打开系统设置的依赖，也不做应用内跳转。
- 不新增第三方依赖；诊断、试听与看门狗都使用 `flutter_tts` 已有接口与 Dart 标准库。

### 6. 真机验收流程

- 构建 release APK，完成权限、签名与版本核对，计算 SHA-256。
- 若 `adb devices` 显示设备，使用 `adb install -r` 安装；否则把 APK 传输到手机后手动安装。不擅自开启本地网络服务。
- 验收在飞行模式下进行，按以下顺序执行：
  1. 冷启动，确认内置一页纸加载完成；
  2. 打开磨耳朵，确认诊断行、试听按钮与试听音频；
  3. 开始整队朗读，验证暂停/继续、上一条/下一条、语速切换与循环；
  4. 在系统设置中停用中文语音，或切换到不含中文语音的引擎，重开播控条，确认提示与重试；恢复语音后重试成功；
  5. 设置若干条目的三态与标星、记录一套真题、启动计时器，强制停止后重新打开，确认状态保留；
  6. 从手机文件中选择 `.md` 导入，确认摘要与写入；导出后再次导入，确认按 `id` 命中；
  7. 走通反射场四种模式、工具箱两段与作战室的计时/计分/折线图。
- 记录设备型号、Android 版本、语音引擎、所选语言、APK 版本与 SHA-256、每项结果。TTS 异常时抓取 `adb logcat` 中语音相关日志并附在记录中。
- 模拟器只用于 UI 与队列回归；模拟器以无音频方式运行，不能替代真机听感验收。

### 7. 交付文档

- 用简短的构建、安装与验收说明替换当前的 Flutter 模板 README。
- 文档包含：应用用途与四 Tab 概览、构建命令、APK 输出位置、个人侧载签名说明、安装方式、TTS 故障排查、验收清单入口与已知边界。
- README 不复制完整规格；需要细节时链接到本规格与冻结实施基线。

### 8. 范围守卫

- 不改学习算法、三态语义、seed 内容、Markdown 协议与四 Tab 的信息结构。
- 不引入新依赖，不改工具链版本，不静默安装任何组件。`aapt2`、`apksigner`、`keytool` 使用现有 Android SDK 与 JDK。
- 现有 20 个测试必须保持通过；新增测试只覆盖 TTS 服务的外部行为。

## Testing Decisions

### 什么算好的测试

只测试外部可观察行为：给定语言列表、引擎返回值与错误/超时，服务是否选择正确语言、是否进入可用/不可用状态、是否按顺序朗读、是否在失败时跳过或降级、是否避免重叠朗读。不断言私有字段、日志文字或实现细节；测试必须确定性、无平台通道、可单独运行。

### 测试接缝

- 复用现有接缝：`TtsService` 构造时注入 `FlutterTts` 实例。测试用一个覆写平台方法的假引擎，记录朗读文本、控制并发数，并可手动完成、报错或永不完成。
- 不新增 widget 测试接缝，不改 UI 结构测试；播控条外观与真机音频由验收清单覆盖。
- 超时与停顿通过构造参数注入，试听通过公开方法调用，避免测试等待 60 秒；这是现有服务构造函数上的测试钩子，不扩散到 UI 或存储层。
- 如果 `FlutterTts` 在当前版本无法稳定伪造，才在 `TtsService` 边界引入最小语音引擎接口；接口只包含初始化、朗读、停止与错误回调，不新增第二处接缝。

### 需要覆盖的 TTS 行为

1. 仅 `zh-CN` 可用时选择 `zh-CN`，状态为可用。
2. 仅 `zh-TW` 可用时选择 `zh-TW`，不因硬编码 `zh-CN` 失败。
3. 语言列表为空但 `isLanguageAvailable('zh-CN')` 为真时仍可用。
4. 完全没有中文时状态为不可用，播放调用不产生朗读。
5. `setLanguage('zh-CN')` 返回失败但 `zh-TW` 成功时回退到 `zh-TW`。
6. `speak` 永不完成时看门狗触发，索引前进，失败计数增加。
7. 平台错误回调触发时立即结束当前等待，不等待看门狗。
8. `speak` 抛异常或返回 0 时按失败处理，循环继续。
9. 连续 3 条失败后停止整队并进入降级态。
10. 快速播放、暂停、继续不会产生重叠朗读；最大并发朗读数为 1。
11. 播放中调用下一条只朗读新索引一次，旧索引不再推进。
12. 暂停后继续从当前索引开始，不回到 0。
13. 循环模式在一轮结束后回到索引 0。
14. 试听不改变队列索引，不写入学习状态。
15. 是非条目的朗读文本包含“正确/错误”与解析；该格式化逻辑由纯函数单元测试覆盖。

### 构建与真机验证

- 运行现有 `flutter analyze`、`flutter test` 与 release 构建，确认 0 error、全部测试通过。
- 对 release APK 执行权限、签名与 badging 检查；把命令与输出摘要写入验收记录。
- 真机按“Implementation Decisions §6”的顺序执行，结果写入验收记录；TTS 音频、系统语音设置交互与覆盖安装只能由真机证明。
- 先例：计时器测试通过注入时钟验证墙钟行为；反射场测试在 service 层验证选题与回写。TTS 测试沿用同样的“纯 Dart 服务 + 注入替身”风格。

## Out of Scope

- 应用商店发布、AAB、Play Console、自动更新与签名密钥管理；本规格只做个人侧载。
- 新建正式 release 密钥库、密钥轮换与团队签名。
- 后台播放、锁屏播放、蓝牙/耳机路由、音频焦点抢占与通话打断处理。
- 下载、捆绑或更新系统语音数据；应用只使用手机已有的 TTS 引擎。
- iOS 与桌面端的真机验收。
- 学习算法、三态语义、seed 内容、Markdown 协议与四 Tab 的视觉改版。
- 进度备份与恢复、云同步、多设备迁移。
- 性能剖析、启动耗时优化、可访问性完整适配。
- 通过应用内跳转打开系统文字转语音设置；只提供文字路径与重试。

## Further Notes

- 制定本规格时 `adb devices` 没有连接设备，因此最终音频验收需要用户把手机连接到本机，或手动传输 APK 安装。代理可以完成构建、权限/签名检查、单元测试、文档与验收清单；真机连接、安装与听感确认是人工检查点，其中听感无法由代理代替。
- `flutter_tts 4.2.5` 的 Android 实现在语音错误回调路径上不会完成 `speak` 返回的 Future；如果只依赖 `awaitSpeakCompletion`，引擎报错时播放循环会永久等待。因此错误回调与超时看门狗都是必需项，不是可选的健壮性增强。
- 当前 debug APK 约 200 MB；release universal APK 预计明显更小。以实际构建结果为准，不为了压缩体积引入 split 或混淆配置，除非 universal 包大到影响传输。
- 应用定位是服务至 2026-12-19 的短期个人工具；本规格优先保证可以安装到手机并日常使用，不为长期维护、商店分发或未来内容同步投入。
